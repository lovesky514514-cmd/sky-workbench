# 4.0 科研主流程迁移

2026-11-08，分支 `dev/sky-next`。目标版本是 4.0。历史 N07 候选的 3.1 标记不代表当前架构版本。首轮只迁移科研主流程；后续完整工程任务已补齐真实模型专家、三维冷却独立审核和隔离 4.0 候选，不重新设计 UI。

## 当前实际链路

`PLAN → ResearchController.plan → ResearchDiscussion → RevisionCoordinator / ExpertScheduler → LLMExpert → ProviderManager.complete_metered`。角色由目标、注册证据、确定性缺口与专家补证请求产生；没有用户可用模型时保留确定性离线草案，不伪造回复。自动发现的本地模型同样进入新总控；不自动启用其他云服务。每次物理模型请求预留预算，保存原请求、严格结构化契约、真实用量或 UNKNOWN、延迟和响应摘要；截断、取消和超时保留消耗，不重放旧请求。

讨论完成后，`prepare_plan → propose_reviewed_plan → planning.propose → 原 ScientificPlanner` 只生成提案。N02 验收与当前计划版本检查通过后才调用发布服务；讨论与提案共享剩余调用/Token 上限，父案例原子领取阻断重复提交。NEEDS_EVIDENCE 只能发布不可 RUN 的草案；`/research/rebind-draft` 只对闲置、未批准草案绑定已有受支持执行契约，不清除未决问题或授予审批。

研究讨论和科学 RUN 在同一 SQLite 中分账。研究检查点使用单独研究身份，没有科学 owner 或 solver 预算；RunJournal 仍是实际运行、attempt、取消、资源和回收的唯一事实来源。研究重启读回检查点后停止无法确认的任务，不自动重放。

## 三维冷却独立复验与交付

既有三维铁块执行器本来就支持对流和灰体辐射。本轮新增的是组织机制及独立审核：总控发现缺少独立观测后，通过原 ToolRegistry/OwnedProcess 的只读进程重开当前已登记 MPH。采集几何、物性表达式、六面选择、时间配置和已存温度/热流历史，不求解、不保存。宿主核对四份冻结收敛 CSV，并以独立 Heun 参考、能量再积分、网格/时间差异重算 15 个物理及证据条件。沿用 20/30/20/15/15 权重及 95 分阈值；任何硬门槛失败均阻断，返工建议为零次求解。

历史真实 COMSOL 6.3 冷却模型已通过源码与实际冻结 Runtime 两种只读采集；原模型/副本 SHA 不变，15 项检查通过，四份旧解历史可回溯。这不是新的 4.0 非标准 RUN。新任务的 5×5×25 mm、600/20 °C、h=15、ε=0.65、180 s 草案已绑定执行器；真实模型参与讨论与提案，但仍保留待审核问题，新的四次内部求解需要单独授权。

`ScientificDelivery` 从完成事件、当前最终 attempt 和冻结字节生成 ZIP，包含模型、原始数值/图片、脱敏记录、Markdown 和 manifest/SHA。运行后的最终审核与报告也进入产物摘要；损坏文件、错项目、旧 attempt 或取消均拒绝导出。历史缺少的原始场不会用解析值补造。讨论报告单独标为 NOT_RUN。现有结果页增加一个导出按钮；原生 4.0 已实际保存并核对历史真实 Heat 成果 ZIP。

## 已测边界

四组同预算对照使用三种有意不完整的合成前提，实际 DeepSeek 共 60 次请求，均安全停在补证状态。SKY 相比全量返工减少调用，但单 Agent 与无反证组更省成本；这些结果不能说明真实科学准确率或完成率优势。引用身份准入不等于语义引用正确率，缺少独立语义评测的指标保留未测。

首个 4.0 候选通过隔离首次安装、3.1→4.0 升级和卸载。纳入知识库污染修复的最终候选通过生产构建、963 文件载荷审计、隔离安装、历史温度场和证据查看、正常退出与卸载。历史 RUN、attempt 和测试文件均保留。最终回归为后端 2162 项通过、14 项历史跳过，前端 129 项、Rust 5 项通过。COMSOL 6.4、MATLAB 和本机 LAMMPS 待实机验收。Materials Studio 通过非计算握手，VASP WSL 通过版本与依赖握手。WebView2 1412 和优雅关闭超时堆栈仍是已知问题。

## 调用链与唯一决策权

迁移前，普通/流式消息都从 `AgentRuntime` 进入 `_plan → _start_run → _execute_run`。旧 `_execute_run` 自行选择工具、循环返工和发布结果。N02、N03、N04 已有真实隔离和审核代码，但定向返工的产品入口主要是模拟 Heat。把它们并置没有完成真实架构迁移。

迁移后，普通/流式 PLAN 都经 `ResearchController.plan → ExpertScheduler → planning.propose`。旧规划器负责生成和检查 ScientificPlan，不启动求解。RUN 经 `ResearchController.start → 原计划绑定/资源准入 → RunJournal.begin_run → ResearchController.execute`。旧 `_execute_run` 只剩兼容委托；原自动返工循环已移除。

总控调用 `RevisionCoordinator + SessionStore` 增补/取消任务，N02 调度、工具白名单和证据上下文负责专家边界。`ExecutionServices` 只提供预检、单次执行、已有读回验证、人工修正复验和最终落账服务。COMSOL 仍通过原 `ToolRegistry → OwnedProcess → heat_worker` 执行，未新建求解器、审批或 owner 系统。未知提交状态保留原异常链及 UNKNOWN_COMMIT，禁止重复提交。

## 首个真实领域：矩形稳态 Heat

初始图只有计划检查。检查后允许一次执行；执行回执由独立审核检查是否足够。缺少独立模型/场证据时，总控记录补证提案，新增只读采集任务，预算为零次求解。新采集器在另一工作者进程加载已登记 MPH，检查实际启用特征、材料模式、边界选择和九点 T/qx/qy，不调用 solve 或 save，并核对模型前后 SHA256。

模型核查与数值质疑读取经过准入的证据。数值检查通过时取消尚未派发的网格调查；存在反证或缺点时保留调查和恢复建议，禁止自己重新 RUN。独立 `review_heat` 融合模型、场与原执行回执；95 分阈值和 20/30/20/15/15 权重不变，物理门槛先于评分。只有审核通过，总控才调用原结果发布服务。改写文本不会改变输入证据、物理检查或得分。

已有经批准的人工 Heat 修正继续复用原能力。批准后的新计划使旧任务图退休；总控绑定新计划版本重新取证/审核，保留同一科学 run/attempt，不由协调器冒造新科学身份，也不自动增加求解预算。

## 状态、隔离与恢复

RunJournal 是真实科学运行和 COMSOL owner 的唯一事实来源。专家 scope 绑定同一项目、会话、计划版本、run 和 attempt。检查点只记录任务领取、预算和已验收证据，SETTLED 不代表科学 PASS。真实图的写入还必须检查原运行是否活动、未取消并拥有资源；终态图不能继续派发。启动对账将中断运行的子图安全停止，不重放已领取任务。

跨专家交换经 N01/N02 的依赖和输入引用检查。冻结证据使用内容摘要命名、限定目录及大小；外部路径、其他 attempt、未登记引用、修改后的字节均拒收。模型及诊断专家没有通用 shell、Python 或文件访问权限。Recovery 由总控按需调用既有 N02 诊断流程，仅诊断，不拥有研究结论和恢复执行审批权。

## 验收与边界

产品入口正反向测试覆盖补证、反证、取消、计划变化、未知提交、人工修正重绑定、冻结字节及旧判定矩阵。合成底座测试明确不是 COMSOL 实测。旧真实 MPH 已用新采集器只读复验，九点场、材料和边界通过，模型哈希不变。

用户随后明确授权“授权本轮一次 Heat RUN”。已通过原产品 HTTP 入口完成 1 RUN / 1 attempt，新总控按缺证据增补只读采集、取消无效调查，独立审核 PASS / 100；另一个只读进程对 3991 个场节点完成 20 项物理复验，源模型不变、owner 和进程均释放。后端 2104 项、前端 128 项、桌面 Rust 5 项通过；14 项历史测试跳过。详见 完整交付报告。

其他 COMSOL 工作流继续经同一总控的单次执行与原领域验证，但尚未声明获得 Heat 以外的新专家科学审核认证。VASP/LAMMPS 等引擎的现有审批执行底座保留，本轮未扩展其科研任务图。
