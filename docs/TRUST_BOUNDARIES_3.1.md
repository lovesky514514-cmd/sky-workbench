# 3.1 记录与授权边界

本轮采用 DSH 修订建议中的 T1：检测意外损坏、产物错配与过期审批。执行记录位于用户本机，信任运行中的桌面服务及其数据库；不承诺抵抗控制同一系统账户的恶意修改者。

同用户可以同时修改记录、产物和散列，记录内附一个自证哈希不能解决这个问题。本轮没有增加这种防篡改声明，也没有将客户端 JSON、可编辑记录或重算哈希作为独立科学认证。需要 T2/T3 时，应另行设计 OS 隔离服务、外部签名/时间戳及远端只追加记录。

参数批准只由专用服务端补全路径产生。请求必须携带服务器给出的提案 ID、用户看到的候选摘要和预期修订。保存时用 SQLite 事务比较修订；计划、假设台账和旧证据失效事件共同提交。普通保存与 AI 返回不能伪造批准、来源页或科学验证状态。修改已批准假设的值会重新进入待审核状态。

逐项确认记录 `reviewed/manual`；授权使用本次候选记录 `scope`，不会冒充逐项人工确认。两种授权均不等于参数真实、材料性质准确或模型科学有效。

引擎进程只使用过滤后的环境。项目由服务端当前项目解析；读取、取消和下载核对所属项目。受控目录的路径校验包含符号链接、junction 和父目录，读取使用有上限的同一份字节并核对变化。此措施减少替换竞态，不提供对有同用户文件控制权限的攻击者的系统级隔离。

输入哈希对应实际写盘字节；输出收集和下载复核散列。旧无源码绑定记录标记 `LEGACY_UNBOUND`，新记录包含源码树摘要、提交号和 dirty 状态。提交号单独不能识别尚未提交的修改，本轮实际算例另保存对应源码归档。

能力分为 UNAVAILABLE、DETECTED、CONNECTED、INPUT_SUPPORTED、EXERCISED、VALIDATED。安装检测不能授权执行；握手绑定可执行文件散列；真实读回仅将已支持模块提升到 EXERCISED。VALIDATED 需要具体算例与科学验收，通用路径不自动授予。
